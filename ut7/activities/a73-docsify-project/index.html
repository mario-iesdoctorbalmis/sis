Proyecto: portfolio técnico con Docsify y GitHub Pages

Objetivo e ideas del tema

Objetivo: Elaborar documentación valorando y utilizando aplicaciones informáticas de propósito general.

  • c) Realizar tareas de documentación mediante el uso de herramientas ofimáticas.
  • f) Utilizar métodos de búsqueda de documentación técnica mediante el uso de servicios de Internet.

¿Qué es el portfolio?

Section titled “¿Qué es el portfolio?”

Durante el curso construirás un sitio de documentación técnica con Docsify que recoge el trabajo de cada unidad. Lo desarrollarás y verificarás primero en tu propio equipo (http://localhost:3000) y después lo publicarás en GitHub Pages mediante GitHub Actions, de modo que mantengas una copia local reproducible y una versión web siempre actualizada.

El portfolio debe ser legible, reproducible y fácil de mantener. Cada página debe explicar un procedimiento con texto, tablas, código y capturas pertinentes.

Requisitos de la entrega

Section titled “Requisitos de la entrega”
  • Proyecto Docsify creado en GitHub.
  • Entregar la URL de tu página en GitHub (GitHub Pages).
  • index.html configurado con name, loadSidebar y un tema visual.
  • _sidebar.md con la estructura completa del curso.
  • README.md con quién eres, qué es el portfolio y el estado de las unidades.
  • Al menos 2 páginas de contenido real de UT7.
  • Cada página incluye una tabla, un bloque de código y un Callout (en Docsify v5 se usa sintaxis nativa estilo GitHub > [!NOTE], > [!TIP], > [!WARNING]; en Docsify v4 se usan los helpers ?> y !>).
  • El sitio se ha revisado en http://localhost:3000.
  • Se añade como colaborador al profesor: mario@iesdoctorbalmis.com

Instalación de Node.js, pnpm y Docsify (Windows)

Section titled “Instalación de Node.js, pnpm y Docsify (Windows)”

1. Instalar Node.js y pnpm (en PowerShell)

Section titled “1. Instalar Node.js y pnpm (en PowerShell)”

Reinicia VS Code y las terminales abiertas para que el sistema cargue las nuevas rutas (PATH).

2. Instalar y arrancar Docsify (en CMD)

Section titled “2. Instalar y arrancar Docsify (en CMD)”

Usa CMD y no PowerShell

Para instalar y ejecutar Docsify debéis usar CMD (Símbolo del sistema) y no PowerShell: la política de ejecución por defecto de PowerShell (Restricted) bloquea los scripts .ps1 de paquetes globales, mientras que CMD ejecuta los lanzadores .cmd.

./docs es la carpeta donde irá el proyecto; cámbiala si fuese necesario.

Flujo de trabajo local

Section titled “Flujo de trabajo local”
  1. Edita los archivos Markdown con VS Code.
  2. Arranca el servidor local con docsify serve ..
  3. Abre http://localhost:3000 y navega por todas las secciones.
  4. Comprueba enlaces, tablas, bloques de código, imágenes y capturas.
  5. Sube los cambios a la rama main (git add ., git commit, git push) y comprueba que se publican correctamente en GitHub Pages (también puedes imprimir la vista en PDF desde el navegador como respaldo).

A tener en cuenta en github

Para publicar tu proyecto de Docsify en GitHub Pages y que se actualice automáticamente en cada git push a la rama principal (main), lo más limpio y fiable es usar GitHub Actions junto con la carpeta ./docs que ya creaste.

2. Activar GitHub Pages en el repositorio

Section titled “2. Activar GitHub Pages en el repositorio”
  1. Entra en tu repositorio en GitHub.
  2. Ve a Settings → Pages.
  3. En Build and deployment → Source, selecciona GitHub Actions.

Recordatorio clave para Docsify

Section titled “Recordatorio clave para Docsify”

Asegúrate de que dentro de ./docs exista el archivo .nojekyll (lo genera docsify init). GitHub Pages lo usa para no ignorar archivos o carpetas que empiecen por _ (como _sidebar.md o _coverpage.md).
