2. Primeros pasos con MkDocs

Section titled “2. Primeros pasos con MkDocs”

2.1. Instala MkDocs y Material for MkDocs en tu equipo. Verifica la instalación con mkdocs --version y documenta el resultado.

2.2. Crea un nuevo proyecto MkDocs con el nombre documentacion-ut7. Describe la estructura de ficheros generada y explica para qué sirve cada elemento.

2.3. Modifica el fichero mkdocs.yml para:

  • Cambiar el site_name a tu nombre completo + “UT7”.
  • Activar el tema Material con idioma español.
  • Añadir la función content.code.copy.

2.4. Arranca el servidor de previsualización con mkdocs serve. ¿En qué URL se sirve el sitio? ¿Qué ocurre si modificas y guardas docs/index.md mientras el servidor está activo?

3. Contenido en Markdown

Section titled “3. Contenido en Markdown”

3.1. Crea un fichero docs/instalacion.md con la siguiente estructura y rellénala correctamente en Markdown:

  • Título H1: “Guía de instalación”
  • Sección H2: “Requisitos del sistema” con una tabla de 3 columnas (Componente, Mínimo, Recomendado)
  • Sección H2: “Pasos de instalación” con una lista numerada de al menos 4 pasos
  • Un bloque de código bash con al menos 2 comandos
  • Una admonición !!! tip con un consejo

3.2. Añade instalacion.md a la navegación del mkdocs.yml bajo la clave nav. Verifica que aparece en el menú lateral.

3.3. ¿Cuál es la diferencia entre usar !!! note, !!! warning y !!! tip en Material for MkDocs? Pon un ejemplo de cuándo usarías cada uno en documentación técnica.

4. Git y GitHub

Section titled “4. Git y GitHub”

4.1. Inicializa un repositorio Git en la carpeta del proyecto MkDocs. Crea un fichero .gitignore que excluya la carpeta site/. Explica por qué no debe versionarse site/.

4.2. Realiza el primer commit con el mensaje feat: (UT7) estructura inicial del sitio MkDocs. ¿Qué ficheros incluyes? ¿Por qué?

4.3. Crea un repositorio público en GitHub con el nombre documentacion-ut7. Conecta tu repositorio local y sube los cambios. ¿Qué comandos has utilizado?

4.4. Realiza un cambio en docs/index.md (añade una línea de texto). Guarda, haz commit y push. Comprueba en GitHub que el cambio aparece en el repositorio.

5. Publicación en GitHub Pages

Section titled “5. Publicación en GitHub Pages”

5.1. Publica el sitio con mkdocs gh-deploy. ¿Qué rama se crea en GitHub? ¿Cuál es la URL pública del sitio?

5.2. Crea el fichero .github/workflows/deploy.yml con el workflow de GitHub Actions para publicar automáticamente en cada push a main. Realiza un cambio en el contenido, haz push y comprueba que la acción se ejecuta en la pestaña Actions de GitHub.

6. Proyecto final

Section titled “6. Proyecto final”

Todos los ejercicios de los apartados 1 al 5 se han ido construyendo dentro del mismo repositorio Git alojado en GitHub (ejercicios-ut7). En este apartado se integran y verifican todos los requisitos:

  • Al menos 3 páginas de contenido en docs/.
  • mkdocs.yml con site_name, site_url, repo_url, tema Material en español y navegación nav completa.
  • Al menos una tabla, un bloque de código y una admonición por página.
  • Repositorio en GitHub con historial de commits con mensajes descriptivos.
  • Sitio publicado en GitHub Pages con URL funcional.
  • Workflow de GitHub Actions que automatice la publicación.
