Servidor de Ficheros (File Server)

Conexión con el currículum

RA 6: Opera sistemas en red gestionando sus recursos e identificando las restricciones de seguridad existentes.

  • a) Se ha configurado el acceso a recursos locales y recursos de red.
  • c) Se han explotado servidores de ficheros, servidores de impresión y servidores de aplicaciones.

Servidor de Ficheros

Section titled “Servidor de Ficheros”

Un servidor de ficheros es un servidor dedicado a almacenar y distribuir archivos para los usuarios de la red de forma centralizada. Windows Server incluye el rol File Server dentro de File and Storage Services.

¿Por qué usar un servidor de ficheros?

Section titled “¿Por qué usar un servidor de ficheros?”
Sin servidor de ficheros Con servidor de ficheros
Archivos dispersos en cada PC Datos centralizados en un único punto
Sin control de quién accede Permisos por usuario y grupo
Copias de seguridad individuales Una sola copia de seguridad del servidor
Sin auditoría de accesos Registro de quién lee o modifica cada archivo
Sin límites de espacio Cuotas de disco por usuario o carpeta (FSRM)

Instalación del rol File Server

Section titled “Instalación del rol File Server”
  1. Abre Server Manager
  2. Haz clic en Manage → Add Roles and Features
  3. En Server Roles, despliega File and Storage Services → File and iSCSI Services
  4. Marca File Server (y opcionalmente File Server Resource Manager para cuotas)
  5. Finaliza la instalación y espera a que se complete

¿Ya está instalado?

En muchas instalaciones de Windows Server el rol File Server ya está habilitado por defecto. Compruébalo en Server Manager → File and Storage Services → Shares.

Creación de carpetas compartidas

Section titled “Creación de carpetas compartidas”

Método 1 — Desde el Explorador de archivos

Section titled “Método 1 — Desde el Explorador de archivos”
  1. Crea la carpeta en el servidor (p. ej. C:\Compartido\Proyectos)
  2. Clic derecho → Propiedades → Compartir → Uso compartido avanzado
  3. Marca Compartir esta carpeta
  4. Asigna un nombre de recurso compartido (p. ej. Proyectos)
  5. Haz clic en Permisos y configura los grupos con el nivel de acceso deseado:
    • Leer — Solo pueden ver y copiar archivos
    • Cambiar — Pueden leer, crear, modificar y eliminar
    • Control total — Pueden hacer todo lo anterior y cambiar permisos

Método 2 — Desde Server Manager

Section titled “Método 2 — Desde Server Manager”
  1. En Server Manager → File and Storage Services → Shares
  2. Haz clic en Tasks → New Share…
  3. Selecciona el perfil de recurso compartido:
    • SMB Share – Quick — Configuración básica
    • SMB Share – Advanced — Incluye clasificación y cuotas con FSRM
  4. Selecciona la carpeta, asigna nombre y permisos
  5. Finaliza el asistente

Permisos: NTFS vs. Recurso compartido

Section titled “Permisos: NTFS vs. Recurso compartido”

Cuando una carpeta está compartida, el acceso efectivo es el más restrictivo entre los permisos NTFS y los permisos del recurso compartido.

Usuario Perm. Share Perm. NTFS Acceso efectivo
Usuario A Control total Solo lectura Solo lectura
Usuario B Lectura Control total Lectura
Usuario C Cambiar Modificar Modificar

Práctica recomendada

Configura los permisos del recurso compartido como Control total para Todos y gestiona el acceso exclusivamente mediante permisos NTFS. Así tienes más granularidad y evitas confusiones.

Conectar unidad de red (acceso persistente)

Section titled “Conectar unidad de red (acceso persistente)”

Para que el recurso esté siempre disponible como unidad de red:

  1. Clic derecho en Este equipo → Conectar a unidad de red
  2. Asigna una letra de unidad (p. ej. Z:)
  3. Introduce la ruta: \\WS-apellidoNombre\Proyectos
  4. Marca Volver a conectar al iniciar sesión y, si el equipo está en el dominio, Conectar con credenciales diferentes si fuera necesario

Despliegue automático con GPO

Section titled “Despliegue automático con GPO”

Para asignar automáticamente la unidad de red a todos los usuarios del dominio:

  1. Abre gpmc.msc (Group Policy Management)
  2. Edita o crea una GPO aplicada a la OU correspondiente
  3. Ve a User Configuration → Preferences → Windows Settings → Drive Maps
  4. Clic derecho → New → Mapped Drive
  5. Configura la letra de unidad, la ruta UNC y la acción (Create o Replace)
  6. Aplica la GPO

Protocolo SMB

Section titled “Protocolo SMB”

El protocolo SMB (Server Message Block) es el estándar de Microsoft para compartir archivos e impresoras en red.

Versión Introducida en Notas
SMB 1.0 Windows NT Obsoleto y vulnerable (EternalBlue / WannaCry)
SMB 2.0 Vista / Server 2008 Mejora de rendimiento significativa
SMB 2.1 7 / Server 2008 R2 Mejoras adicionales de eficiencia
SMB 3.0 8 / Server 2012 Cifrado, failover, multicanal
SMB 3.1.1 10 / Server 2016 Seguridad y rendimiento mejorados

Seguridad: deshabilitar SMB 1.0

SMB 1.0 debe deshabilitarse en todos los sistemas modernos. Es el protocolo que explotó el ransomware WannaCry en 2017.

DFS — Sistema de archivos distribuido

Section titled “DFS — Sistema de archivos distribuido”

DFS (Distributed File System) permite crear un espacio de nombres unificado que agrupa múltiples servidores de ficheros bajo una única ruta, de forma transparente para el usuario.

  • Espacio de nombres DFS: \\inforclass.local\datos apunta a uno o varios servidores físicos
  • Replicación DFS: Sincroniza automáticamente carpetas entre servidores para redundancia
  • Ideal para organizaciones con varias sedes o cuando se necesita alta disponibilidad

Transparencia para el usuario

Con DFS los usuarios acceden siempre a la misma ruta aunque el servidor físico cambie o falle. El cambio de servidor es transparente y automático.
